# 02 · 数据与接口契约

版本 1.0。本文件定义业务语义，不是已经存在的接口。执行 Agent 不得将示例路径误当成第三方真实 API。推荐实现为 TypeScript 领域模块 + Fastify API + SQLite；关键规则不放进 React 组件。

## 1. 通用约定

- 实体 ID：生产使用服务端生成的 UUIDv7（或明确 ADR 采用 UUIDv4），不混用展示题号。示例 `q03` 等短 ID 仅用于固定测试夹具。
- 时间：API 使用 ISO 8601 UTC；另存工作区 IANA 时区如 `Asia/Shanghai`。日期任务使用 `YYYY-MM-DD` + 创建时区。
- 时长：非负整数毫秒；分数：非负整数 `score_units`，100 units = 1 分；禁止浮点判分。
- 版本：记录修订使用递增正整数；内容协议使用 SemVer，如 `1.0.0`。已发布版本不可原位变更。
- 文本：UTF-8、统一 LF、Unicode NFC；原始答案另存原文，归一化值只用于比较，不覆盖展示值。
- 默认单工作区。全部查询仍显式限定 workspace_id，避免未来切换时串库。
- P0 不做分布式并发；SQLite 一写多读，写事务短小，外部 IO 不能放在事务中。
- 列表分页默认 30、最大 100，返回稳定游标和 `has_more`；游标按排序值+ID 编码，过滤变化重新开始。

### 2.1 关系与约束

- Source→Asset 可选；多个材料可共享同一资产。删 staging 时仅删无正式引用且超过宽限期的资产。
- QuestionVersion 持有 MaterialVersion 的确定版本。历史版本有外键保护，禁止级联物理删除。
- AttemptItem 的完整快照用于长期独立导出；同时保存原始版本 ID 便于追溯。
- `UNIQUE(attempt_id, order)`、`UNIQUE(attempt_id, action_id)`、`UNIQUE(attempt_id)` on Submission。
- `UNIQUE(attempt_id, version)` on GradeRevision/ExternalReviewRevision/UserNoteRevision/ReportRevision。
- 用逻辑快照序列化固定字段顺序；hash 不包含操作系统路径或不稳定对象顺序。
- UI 的第3题可能对应任何 ID，答案引用 option_id 而不是 A/B/C/D 的显示字母。

## 3. 题目协议与判分策略

### 3.1 题型

| type | answer 结构 | answer_key | P0 规则 |
|---|---|---|---|
| single_choice | `{selected_option_ids:[id]}` 或 null | 同结构且恰好一项 | ID 完全一致 |
| multiple_choice | `{selected_option_ids:[id,...]}` 或 null | 非空唯一 ID 集合 | 去重后集合完全相等得满分，否则零分 |
| true_false | `{value:true/false}` 或 null | value 布尔 | 严格布尔相等，false 不是未答 |
| fill_blank | `{blanks:[{blank_id,text}]}` 或 null | 每空 `accepted_values[]`、归一化策略、分值 | 每空精确匹配可接受值，按显式空分值相加 |
| free_text | `{text:string}` 或 null | 可有参考答案和 rubric，不等于自动判分 key | 待人工评分 |

组合题不是第六种判分类型：多个基础题共享材料并归组。考研匹配题用稳定选项 ID 建模，允许题目间复用选项的规则必须在题集元数据中声明；完形每空作为单选子题。

### 3.2 校验

题干不超过 50,000 字符；单选选项 2–10 个；选项 ID 非空唯一；每项文本不超过 10,000 字符；自由文本答案最大 50,000 字符；原始思路最大 10,000 字符。前后端共享上限和错误码，生成图片里的数字不构成限制。

`max_score_units` 为 1–1,000,000 整数；填空各空分值之和必须等于本题满分。允许零权重题需要后续显式协议升级，P0 不默认支持。

填空可设置 `trim_outer_whitespace=true`、`case_sensitive=true/false`、`collapse_internal_whitespace=true/false`；必须逐题写入版本。NFC 统一但不默认 NFKC，不忽略重音符号、标点或词序；空字符串始终视为空白作答而非正确答案。

### 3.3 判分结果

每个 item 返回 `answer_status: answered|unanswered`；`grading_status: graded|pending|invalid`；`correctness: correct|incorrect|partial|unanswered|null`；`earned_score_units: integer|null`；`max_score_units`；`basis`。

- 有 key 的单选/多选/判断，未答：graded、unanswered、0。
- 无 key 的客观题：pending、correctness=null、earned=null，即使未答也不伪装已判。
- 自由文本无论空白与否先 pending；人工可明确给空白 0 分。
- 部分填写的填空算 answered，按每空判分；得分在 0 与满分之间标 partial。
- 客观题 key 无效/缺引用：invalid、earned=null、显示需修正，不能因错误 key 判用户零分。
- 自信程度不参与分数计算，不奖励思路长度或点击速度。

### 3.4 统计口径

`total_max = sum(all max)`；`graded_max = sum(max where graded)`；`earned = sum(earned where graded)`；`pending_max = sum(max where pending or invalid)`；必须满足 `graded_max + pending_max = total_max`。

`score_rate = earned / graded_max`，分母 0 返回 null 并显示“暂无已判成绩”，不是 0%。有 pending 时禁止仅显示 `earned/total_max` 暗示最终成绩。

客观题正确率：全对客观题数 / 已判客观题数，其中未答已判题计入分母；部分对不算全对。已答正确率：全对已答客观题 / 已答且已判客观题。两者明确不同，不混称正确率。

`answered_count` 统计任何有内容的答案，不能用 truthy 判断 false；`incorrect_count` 仅已答全错，未答另算。摘要还需 `partial_count`、`pending_count`、`invalid_count`。

百分比显示一位小数，整数比值先精确计算再统一 half-up；整数恰好百分数可 UI 简写，导出保留口径。趋势默认按同题集/同满分/同模式分组；混合试卷不直接平均分数。

### 3.5 修订

人工评分需 `source=manual|self_assessed`、理由、每题分值；不能覆盖确定性 key，可创建人工覆盖的新 GradeRevision，明确标注覆盖来源。题目纠错创建新 QuestionVersion，但重评历史题采用显式 `regrade_basis`，保存旧快照与纠正 key 的对应关系。

外部Agent只能在review.md的grading_concerns中提出异议，不接受可直接写回成绩的分数字段。用户阅读后若人工改分，以source=manual或self_assessed创建评分修订，并可引用ExternalReviewRevision ID作为参考来源；不能把文件校验通过当成用户确认。

## 4. 状态机

### 4.1 Attempt

`draft → in_progress ↔ paused → submitted`；`in_progress → submitted`；`draft|in_progress|paused → abandoned`。

- paused 只对训练允许；严格限时返回 `MODE_FORBIDS_PAUSE`。
- submitted/abandoned 不可回到可编辑。重做是新 Attempt。
- `submitting` 仅为客户端过渡态，不单独持久化为长期业务状态。
- 报告失败不回退 submitted。
- abandoned 保留已有事实和草稿，可导出说明但不进入正式成绩统计。

### 4.2 Job

`queued → running → succeeded|failed|cancelled`；running 租约过期重新 queued，尝试次数加一；只对声明为可重试的错误重试。`cancel_requested` 是请求标记，不等于远端操作已经撤回。

报告/上下文文件任务最多执行3次：首次立即，第二次等待2秒，第三次等待10秒，之后终止并允许人工重试。网页不创建AI请求任务，也不控制外部Harness的调用重试和费用。

### 4.3 ImportSession

`uploaded → parsing → needs_review → committed|cancelled|expired`；解析失败返回 needs_review 带错误或 failed 可重传。committed 重复确认返回相同结果，不重复导入。

## 5. 草稿同步与多标签页

### 5.1 客户端队列

IndexedDB 存待同步动作，不作为正式成绩源。每条动作有随机 action_id、attempt_id、writer_epoch、client_seq、expected_draft_revision、changed_fields、occurred_at。

选择题立即加入队列；文本 compositionend 后 300ms 本地合并，后端 800ms 防抖，失焦触发。合并只能合并尚未发送的同字段动作，不改已发送动作的幂等 ID/请求体。

服务端先校验租约、Attempt 状态/截止、题目归属、字段，再根据 expected_revision compare-and-swap 更新。返回 accepted_revision 和 saved_at。客户端仅删除已回执动作，不能在发起请求时就删除队列。

同一 action_id、相同 payload 重放返回原回执；同 ID 不同 payload 返回 `IDEMPOTENCY_CONFLICT`。

### 5.2 写租约

每个 Attempt 只有一个活跃 writer，租约 30s，每 10s 续约；所有写操作带 epoch。接管需要用户确认，服务器原子提升 epoch，旧页所有写入被拒绝，旧队列不自动提交到新 epoch。

租约到期的同页可在无他人持有时显式续租，升 epoch 后先拉最新草稿、逐项对照本地差异；不无条件重放。冲突文本保留两份供用户选择，选择题不做自动“最后写入者胜”。

### 5.3 保存时序

用户操作 → 浏览器写队列成功 → UI 乐观展示“暂存” → HTTP 写入 → 数据库提交 → 响应回执 → UI 显示“已保存到本机”。

数据库空间不足/锁超时/IO 错误返回可分类错误；不能回应成功后靠后台慢写。SQLite durability 配置要与承诺匹配：发布前验证 WAL+`synchronous=FULL` 和备份流程。

## 6. 提交事务

POST submit 带 `Idempotency-Key`、`expected_attempt_revision`、`last_acknowledged_action_ids` 或等价高水位。前端先同步所有当前草稿。

同一数据库写事务中：

1. 检查已有 Submission：同请求返回原结果；不同键但已提交也返回现有 Submission，不创建第二份。
2. 校验状态、版本、模式、deadline、epoch（系统到期提交不使用浏览器租约）。
3. 从已确认 AnswerDraft 生成不可变 AnswerSnapshot；固化计时质量与展示顺序。
4. 设置 submitted_at/reason，生成 snapshot_hash。
5. 基于纯函数生成初始 GradeRevision（P0 题量上限 500，禁止外部网络调用）。
6. 创建绑定具体评分/复盘输入的 ReportRevision、去重报告 Job，以及自动准备 AgentPackage 的去重 Job；上下文文件实际写入在事务外。
7. 提交事务，返回 Submission 与报告任务 ID。

宕机发生在 commit 前：全部回滚，可重试；发生在 commit 后响应前：重试/GET 得到已有 Submission。报告实际文件生成在事务外，先写临时文件，校验成功原子发布，最后标记 ready。

## 7. 计时契约

### 7.1 训练

记录 started_at、submitted_at、pause intervals、visibility events、题目切换、心跳。心跳间隔 10s。正常同进程活动间隔使用 monotonic clock；`Date.now` 只做展示和事件绝对时间，不直接累加不可信的大间隔。

有效时间 `active_ms = item_ms_sum + material_ms + unattributed_ms`。paused_ms、hidden_ms、unknown_ms 单列，不计入 active。墙钟跨度近似满足 `elapsed_ms = active_ms + paused_ms + hidden_ms + unknown_ms`，允许毫秒边界取整误差但不得重叠双计。

连续心跳间隔 >30s 时仅确认前30s内可验证区间，其余标 unknown；恢复后开启新段，不能将电脑休眠算作某一题专注时间。正式报告记录 `timing_quality=complete|partial|clock_anomaly`。

注意：时钟一致并不意味着用户实际一直思考；报告必须使用“前台有效时间”，不是“真实思考时间”。

### 7.2 严格限时

deadline 在开始时固定为服务端 UTC；进程运行中使用 monotonic 剩余时间校验，外部墙钟跳变不会延长当前服务进程的考试。服务重启后用已保存 deadline 恢复；如果检测系统时间大幅倒退，锁定练习并标 clock_anomaly，需要用户选择转为非严格训练副本或接受异常标记，不默默延长。

已停止的电脑没有可信硬件时钟，本地系统不能提供防作弊保证；报告清楚记录服务中断。服务恢复后，若 deadline 已过，立即基于截止前已接收草稿提交。API 使用 `received_at` 判定是否迟到，不能相信客户端自行填写的 occurred_at。

deadline 与写入同事务内判断；边界为 `received_at < deadline` 接收，`>= deadline` 拒绝。Worker 不及时运行也不能导致 API 多接收答案。

### 7.3 迟到草稿

单独保存 `late_draft` 导出副本；带明确 `excluded_from_official_submission=true`。不得回填成绩，用户可创建训练 Attempt 继续研究。

## 8. HTTP 契约

### 8.1 基础

前缀 `/api/v1`；同源 JSON API。成功格式 `{data, meta:{request_id,revision?}}`。失败 `{error:{code,message,retryable,field_errors?,conflict_revision?},request_id}`。错误信息不包含密钥、SQL、内部堆栈、用户绝对路径。

状态码：400 格式、401 本机会话无效、403 Origin/CSRF 不允许、404 不存在、409 状态/版本冲突、413 太大、422 业务校验、429 限流、503 本机存储/服务暂不可用。统一错误码至少包含 SAVE_FAILED、DISK_FULL、LEASE_LOST、REVISION_CONFLICT、DEADLINE_PASSED、INVALID_ANSWER_KEY、REPORT_FAILED。

PUT/PATCH 等更改带 `If-Match` 修订号或请求体 expected_revision（二选一全系统一致）；创建/提交/导入/报告任务用 `Idempotency-Key`。幂等记录至少保留该工作区存续期中的提交/导入记录；临时配置请求至少24小时。

### 8.3 报告、评分、复盘 API

## 9. 固定样本与统计验收

以 `examples/完整复盘报告-演示.md` 为黄金样本：5 道单选，每题 200 units；Q1 B/B，Q2 C/C，Q3 A/B，Q4 D/D，Q5 null/A。前项为用户作答，后项为 key。

预期：earned=600、graded_max=1000、total_max=1000、pending_max=0；answered=4、correct=3、incorrect=1、unanswered=1、partial=0、pending=0。客观正确率60.0%，已答正确率75.0%，得分率60.0%。

计时：墙钟1122s、暂停162s、有效960s、隐藏0s、未知0s。题目150+180+210+160+80=780s，共享阅读180s，总有效960s。

独立待评案例：在上述五题另加一道满分1000 units的自由文本，未人工评分。预期 earned=600、graded_max=1000、total_max=2000、pending_max=1000；显示“已判 6/10，另有10分待评；整卷20分”，不能写成最终6/20。

## 10. 迁移、备份与 Worker

- 每个迁移带版本、校验和及可回滚说明；破坏性迁移之前验证可恢复备份，失败不启动读写业务。
- Worker 与 API 分进程但共用同一工作区，默认一名 Worker。SQLite Job 领取在事务中条件更新 lease；不使用 Redis。
- 任务输入是已固化版本引用，避免“排队时旧版本，执行时读取最新内容”。
- API/Worker 可重复启动，租约防止同任务并发；文件产出按 input_hash 幂等，临时文件有受控生命周期。
- 备份期间暂停内容写入短窗口并取得一致数据库快照及资产清单；清单内资产不可在备份完成前垃圾回收。
- 恢复先校验安全路径、协议版本、摘要、外键和统计数量，再创建新工作区。不得运行备份内任何脚本。
- 关闭服务先拒绝新写入、完成短事务、持久化队列，再停止进程；超时中止不破坏事务原子性。
